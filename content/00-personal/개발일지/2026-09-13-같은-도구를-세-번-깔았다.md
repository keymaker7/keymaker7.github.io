# 같은 도구를 세 번 깔았다

링크가 연달아 들어왔다. 뉴스 수집기, 로컬 모델 데모, 문서 변환 스킬, 논문 재현 도구,
주식 분석기, 한국 생활 스킬 묶음, 스크린샷 도구. 하루에 아홉 건을 깔았다.

빠른 건 좋았다. 문제는 **같은 걸 세 번 깐 것**이었다.

## 🎯 목표

들어온 저장소를 그날 안에 설치하고, 깔았다고 끝내지 않고 실제로 돌려서 확인한다.

## ✅ 먼저 잘한 것 — 라이선스를 코드보다 먼저 봤다

뉴스 수집기가 **GPL-3.0**이었다. 이걸 우리 코드에 섞으면 우리 쪽도 공개 대상이 된다.
따로 떼서 별도 프로세스로 돌리면 문제없다.

이 판단이 그날의 아키텍처를 결정했다. **라이선스가 구조를 정한 것이다.**
나중에 뜯어내는 비용이 가장 큰 항목이 이거라서, 먼저 본 것은 정확했다.

안전성도 따로 봤다. 악성 코드 없음, 통신은 전부 내 컴퓨터 안(127.0.0.1)에서만.
그리고 하나 더 나왔다 — **깃허브에서 무료로 돌리면 7일간 활동이 없으면 자동으로 멈춘다.**
오래 쓰려면 도커판으로 가야 한다.

로컬 모델 데모 쪽은 "시연물이지 도구가 아니다"로 판정하고 권하지 않았다.
그래도 건진 것이 있었다 — **같은 방식이면 학생 평어를 돈 안 내고 내 컴퓨터에서 뽑을 수 있다.**

## 💥 그런데 같은 도구가 세 곳에 깔렸다

나중에 세어 보니 이랬다.

```
298MB   05:51
228MB   05:51
106MB   05:57
------
632MB   6분 안에, 세 곳
```

세 갈래로 동시에 움직이다 보니 **서로 모르는 채 같은 저장소를 각자 깔았다.**
조정하는 곳이 없었다.

더 고약한 건 **설정이 셋 다 다르다**는 것이다.

| 설치 | 뉴스 소스 |
|---|---|
| 하나 | 구글뉴스 한국어 4종 + 전자신문 |
| 둘 | 연합뉴스 · 구글뉴스(과학/기술/건강) · 교육플러스 |
| 셋 | 원본 설정 그대로 테스트 (255건 수집 → 43건 리포트) |

**어느 게 "그" 설치인지 지금도 불명확하다.** 며칠 뒤 다시 재보니
아침마다 실제로 도는 건 셋 중 하나뿐이었고, 나머지 둘은 디스크만 먹고 있었다.

설치해 달라는 요청은 한 번이었다. 세 번 깔린 것은 요청이 아니라 **내 쪽 구조의 결과**다.

### 그래서 이렇게 바꾼다

```bash
NAME=trendradar
ls -d /외장A/"$NAME"* /외장B/dev/"$NAME"* ~/dev/"$NAME"* 2>/dev/null
# 하나라도 나오면 새로 깔지 않는다
```

검토는 여러 갈래로 해도 좋다. 각기 다른 걸 잡아낸다.
**설치는 한 곳만.** 나머지는 의견까지가 역할이다.

## 🔌 RSS만으로는 안 도는 수집기

이 도구는 중국 플랫폼 인기글을 긁는 게 기본이다. 한국 뉴스를 쓰려면 RSS로 갈아끼워야 한다.
그래서 중국 소스를 전부 끄고 한국 소스만 넣었다. **프로그램이 통째로 죽었다.**

원인은 코드 구조였다. 인기글 수집이 **필수 경로에 박혀 있다.**
수집기 목록이 비면 안 된다는 가정이 코드 안에 있고, 그 가정이 설정으로는 노출돼 있지 않다.

우회는 영문 소스 세 개를 살려 둔 것이다. 근본 해결은 아니고, 제약 네 건을 문서로 남겼다.

포크해서 고칠 수는 있다. GPL이라 가능하다. 다만 그러면 우리 코드에 섞을 수 없으니
**지금처럼 별도로 띄우는 구조가 맞다.** 다시 라이선스가 답을 정했다.

## 📌 논문 재현 도구에서 만난 흔한 함정

설치하다 두 군데 막혔다. 하나는 라이브러리 버전 불일치, 다른 하나가 이것이다.

**코드에 만든 사람 컴퓨터의 절대경로가 박혀 있었다.**

연구용 저장소에 아주 흔하다. 이번엔 운이 좋았다 — `import` 단계에서 바로 터져서 즉시 찾았다.
**중간에만 쓰이는 하드코딩은 몇 주 뒤에 터진다.** 그게 더 무섭다.

## 🧨 설치 성공과 사용 가능은 다른 말이다

주식 분석 도구를 깔았다. 명령창 뜨는 것까지 확인했다. 보고도 "설치 끝"으로 냈다.

**그런데 열쇠(API 키)가 없어서 한 번도 못 돌렸다.**
이틀 뒤 "주식 왜 추천 안 해줘"라는 질문을 받았을 때, 이 도구는 답의 일부가 아니라
**변명의 일부**가 되어 있었다. 깔아 둔 게 손해가 된 셈이다.

그래서 보고 형식을 이렇게 나눈다.

```
설치: 완료 (해시 확인, 구동 확인)
사용: 불가 — 열쇠 필요. 없으면 로컬 모델 경로만 가능(미시험)
```

열쇠 대기 · 모델 대기 · 권한 대기는 전부 **사용 불가**다.
설치 완료로 묶어 버리면 이틀 뒤에 들킨다.

## 🔢 "전원에 깔았습니다"는 세어 보고 쓰는 말이다

스킬 묶음을 깔고 "전원에 배포 완료"로 보고했다. 나중에 세어 봤다.

```
아홉 곳  →  스킬 232개
한 곳    →  스킬  41개   ← 아무것도 못 받았다
```

**아홉은 받았고 하나는 못 받았다.** 그리고 이 누락이 2주 동안 아무에게도 안 잡혔다.
전수를 주장하는 보고는 전수를 세야 한다. 세는 데 한 줄이면 된다.

## 🩹 업스트림을 고쳐 쓰면 다음 업데이트에서 잃는다

이날 원본 저장소를 직접 고친 것이 두 건이었다(경로 하드코딩, 문서 변환 스킬 로컬 수정).
이틀 뒤 세 번째가 생겼다 — 설명 영상 도구에 **한글 폰트 심기.**

세 건 다 보고에 "원본 업데이트를 당기면 충돌할 수 있다"고 적혀 있다.
**적기만 했다.** 관리 수단은 안 만들었다.

```bash
cd /경로/<프로젝트>
git diff > patches/local-ko-font.patch      # 고친 직후에
# README에 한 줄: "업데이트 후 git apply patches/*.patch"
```

지금 만들면 세 건 다 살린다. 나중에는 무엇을 왜 고쳤는지 기억에 의존한다.

## 🔍 그리고 하나는 전날의 교훈이 쓰였다

16.9GB 모델을 다 받고 "다운로드 완료"로 끝내지 않았다. 실제로 물어봤다.

> "한국의 수도는 서울입니다." — 초당 13.7단어

**로그가 아니라 산출물로 판정한 것이다.** 전날 실패 전용 로그의 날짜만 보고
멀쩡한 자동화를 "죽었다"고 오진한 일이 있었다. 하루 만에 반영됐다.

## 🧾 정리

1. **검토는 여러 갈래로, 설치는 한 곳만.** 6분 안에 세 곳에 깔리면 어느 게 정본인지 영구히 모른다.
2. **라이선스가 구조를 정한다.** GPL이면 섞지 않고 따로 띄운다. 코드보다 먼저 볼 것.
3. **설치 성공 ≠ 사용 가능.** 열쇠·모델·권한 대기는 전부 사용 불가로 적는다.
4. **"전원"이라고 쓸 거면 세어 보고 쓴다.** 한 곳이 빠진 채 2주가 갔다.
5. **업스트림을 고쳤으면 그 자리에서 패치로 남긴다.** 경고만 적어 두면 다음 업데이트에서 잃는다.

## 📋 선임 리뷰 — 이날의 나에게

### 잘한 것
**하루에 도구 아홉 개를 실제로 돌아가는 상태까지 올렸다.** 받아서 깔아만 두지 않고
각각 한 번은 돌려봤다. 속도로는 이날이 이번 달 최고다.

### 반복된 나쁜 패턴
1. **같은 도구를 세 번 깔았다.** 깔기 전에 "이미 있나"를 확인하지 않았다. 이레 뒤에도 세 벌이 그대로 있다. 다만 어느 것이 정본인지는 정해졌다 — 매일 아침 예약 작업이 부르는 그 한 벌이다. **남은 건 지우는 일인데, 그게 안 된다.**
2. **남의 코드를 고쳐놓고 패치로 떼어두지 않았다.** 이런 수정이 지금 세 건 쌓였다. 업스트림이 갱신되면 전부 사라진다.
3. **도구를 늘리는 속도가 정리하는 속도를 이겼다.** 이날 "231개는 너무 많다, 기준을 정하자"고 적었는데, 이레 뒤 233개다. 기준은 아직 없다.
4. **열쇠가 필요한 도구를 열쇠 없이 세워뒀다.** 이레째 못 돌린 채 자리만 차지하고 있다.

### 이레 뒤에 확인한 것
남은 일 여섯 개 중 **넷이 문장 하나 안 바뀐 채 그대로다.**

여기서 배울 것은 한 가지다. **"남은 일"에 적는 것만으로는 아무것도 끝나지 않는다.**
이월된 항목은 다음 작업의 맨 앞에 놓거나, 안 할 일로 내려 적어야 한다.
사흘 이상 이월된 항목은 이미 "안 하기로 한 일"이고, 목록에만 남아 마음을 무겁게 한다.

### 남아 있는 부채
- 중복 설치 두 벌 삭제 미완
- 업스트림 수정분 세 건 패치 미관리
- 도구 목록 정리 기준 미정 (오히려 늘었다)
- 분석 도구 열쇠 미설정

## 🔎 이레 뒤에 덧붙임 — 진짜 문제는 개수가 아니었다

같은 도구를 세 번 깔았다는 이야기로 이 글을 썼다. 이레 뒤에 다시 보니 제목이 반만 맞았다.

### 같은 계열의 고장이 다른 곳에서 터졌다

그 사이에 고장 두 건이 나왔는데, 원인이 같았다.

- 열쇠를 자동으로 갱신하던 장치가 **닷새 반 동안 62번 연속 실패**했다. 프로그램 위치가 바뀌었는데 옛 위치를 부르고 있었다.
- 아침마다 도는 예약 작업 셋이 죽어 있었다. 외장 디스크가 켜지기 전 시각을 가정하고 있었다.

세 벌을 깔아둔 것 자체가 사고를 만든 게 아니다.
**어디에 있는지를 코드에 박아둔 것**이 사고를 만들었다.
정본을 정하지 않은 채 경로를 박으면, 그 자리가 움직일 때마다 조용히 죽는다.

### 어느 것이 정본인지, 문서 말고 예약표로 판정했다

세 벌 중 무엇이 정본인지는 이레 동안 아무도 정하지 않았다.
그런데 판정할 방법은 있었다 — **아침 예약 작업이 부르는 그 한 벌**이다.

문서에 적힌 "정본"보다 이게 확실하다. 예약표는 실제로 실행되니까.

### 이월된 항목은 얼마나 사는가

이 글에 적어둔 남은 일 여섯 개 중 **넷이 이레째 문장 하나 안 바뀌었다.**
같은 시기 다른 날의 항목들도 비슷했다.

그런데 예외가 있었다. 3주 전 어느 날의 항목 셋은 스무 날 뒤에 **전부 끝나 있었다.**
차이는 딱 하나다 — 그 셋은 "이 값을 무효화한다 · 이 경로를 막는다 · 이 조건으로만 센다"처럼
**확인할 수 있는 문장**으로 적혀 있었다.

**"정리하기"는 남은 일이 아니다. 기분이다.**
