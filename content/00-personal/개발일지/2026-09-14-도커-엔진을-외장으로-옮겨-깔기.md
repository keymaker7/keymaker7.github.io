# 도커 엔진을 외장으로 옮겨 깔기

SNS 예약발행 도구 **OpenPost**를 본진 맥미니에 자체호스팅했다.
문제는 부팅 디스크였다. **여유가 거의 없었다.**

## 🎯 목표

내장 디스크를 더 먹지 않고 도커 기반 웹앱을 올린다.

## 🧱 1. Docker Desktop 대신 colima

Docker Desktop은 설치돼 있었지만 한 번도 켜진 적이 없었다.
가볍고, 무엇보다 **VM 위치를 내가 정할 수 있는** colima를 골랐다.

핵심은 환경변수 하나다. colima는 기본적으로 홈 디렉터리에 VM을 만든다.
그대로 두면 30GB짜리 가상 디스크가 내장에 박힌다.

```bash
export COLIMA_HOME=/외장볼륨/colima   # 반드시 colima start 전에
colima start
```

VM 사양은 cpu 4 / mem 6G / disk 30G. macOS Virtualization.Framework 위에서 돌고
파일 공유는 virtiofs다.

## 🐳 2. amd64 전용 이미지를 Apple Silicon에서

OpenPost 공식 이미지는 amd64 빌드만 있다. Apple Silicon에서 네이티브로 안 돈다.
Rosetta 에뮬레이션으로 띄웠다. 성능 손해는 감수하기로 했고,
21시간 연속 가동 후에도 헬스체크는 healthy를 유지 중이다.

구성은 단순하다.

- 이미지: `ghcr.io/getopenpost/openpost:latest`
- DB: SQLite, 도커 named volume
- 비밀값: `.env` 자동 생성 (JWT·암호화 키 2종), 권한 600
- 라이선스: AGPL-3.0

## 🕳️ 3. 함정 — "떴다"는 절반의 검증이다

띄우고 나서 `localhost:8080`이 200을 돌려주는 걸 확인했다. 여기서 끝냈다.
다음 날 운영 문서대로 상태를 확인하려다 이걸 만났다.

```
$ export COLIMA_HOME=/외장볼륨/colima
$ docker ps
failed to connect to the docker API at unix:///var/run/docker.sock
```

`COLIMA_HOME`을 지정해도 **docker 클라이언트는 여전히 기본 소켓을 본다.**
colima의 소켓은 VM 디렉터리 안에 따로 있다. 컨텍스트를 등록하지 않으면
문서에 적어둔 `docker compose down`이 새 셸에서 그대로 실패한다.

한 번만 박아두면 끝나는 일이었다.

```bash
docker context create colima \
  --docker host=unix:///외장볼륨/colima/default/docker.sock
docker context use colima
```

교훈은 이쪽이 크다. **켜는 절차만 확인하고 끄는 절차는 안 돌려봤다.**
인수 조건은 "떴다"가 아니라 "적어둔 대로 껐다 켜진다"여야 한다.

## 🙈 4. 덤으로 밟은 자책골

이 글을 쓰려고 상태를 재는데 `colima status`가 "colima is not running",
`colima list`는 "No instance found"를 뱉었다. 컨테이너가 날아간 줄 알았다.

원인은 같은 것이었다. 셸에 `COLIMA_HOME`이 없어서 기본 경로를 본 것뿐이었다.
환경변수를 주니 멀쩡히 Running이었다. 포트 8080을 물고 있던 수상한 `ssh` 프로세스도
정체는 colima 자신의 SSH 포트포워드였다.

보고서에 "장애 발생"이라고 쓰기 직전에 한 번 더 확인해서 오보는 면했다.
**한 번 더 재보는 30초가 오보 한 건보다 싸다.**

## ✅ 결과

| 항목 | 상태 |
|---|---|
| colima VM | Running (aarch64, cpu4 / mem6G / disk30G, 외장 배치) |
| 컨테이너 | Up 21 hours (healthy) |
| `localhost:8080` | HTTP 200 |
| 내장 디스크 증가분 | 0 |

## 📌 남은 일

- SNS 계정 연결: 플랫폼별 앱 승인 필요(인스타·틱톡·X 등)
- 외부 접속: 공개 URL 설정 교체 + HTTPS 리버스 프록시
- 재부팅 시 자동 기동 설정 없음
- AGPL-3.0 — 따로 돌리는 건 자유지만, 코드에 섞으면 공개 의무가 따라온다

## 정리

내장이 꽉 찬 맥에서 도커를 쓰려면 **엔진 VM째 외장으로 옮기면 된다.**
`COLIMA_HOME` 하나면 되고, 반드시 `colima start` 전에 걸어야 한다.
그리고 옮긴 뒤에는 **docker context 등록을 잊지 말 것.** 잊으면 하루 뒤의 내가 헤맨다.

## 📋 선임 리뷰 — 이날의 나에게

### 잘한 것
**보고 전에 확인해서 오보를 막았다.** 도커가 죽은 줄 알았는데, 실은 셸에 환경변수 하나가 없어
기본 경로를 보고 있었던 것이었다. "날아갔습니다"를 보내기 전에 한 번 더 확인했다.

**포트를 점유한 정체 불명 프로세스도 끝까지 추적했다.** 남의 프로세스가 아니라 도커 자신의 포트 전달이었다.

### 반복된 나쁜 패턴
1. **접수한 요청을 22시간 방치했다.** 링크를 받아 전달까지 하고, 그 뒤 하루가 지났다. 전달은 처리가 아니다.
2. **자체호스팅을 올려놓고 외부에서 쓸 수 없는 상태로 뒀다.** 주소가 내부용 그대로고 암호화도 없다. 엿새 뒤 확인해도 그대로다 — **"일단 떴다"에서 멈추면 쓰이지 않는다.**
3. **도구 등록을 건너뛰었다.** 매번 환경변수를 손으로 넣어야 돌아가는 상태로 남겼다. 그래서 다음에 상태를 확인할 때 또 "죽은 것처럼" 보인다.

### 엿새 뒤에 확인한 것
**올려둔 서비스 둘이 지금 내려가 있다.** 이틀 전 기록에는 나흘째 가동 중이었는데,
지금은 가상 머신 자체가 꺼져 있고 두 포트 모두 응답이 없다.
디스크가 꽉 찼던 날 또는 그 뒤 재시작이 계기로 보이지만 확정하지 못했다.

**여기서 배울 것은 하나다.** 올린 것은 올린 날에만 살아 있는지 확인하고,
그 뒤로는 아무도 안 본다. 조용히 내려가도 알 방법이 없다면 그건 올린 게 아니다.
가동 확인을 사람의 기억이 아니라 **정기 점검 항목**으로 옮겨야 한다.

### 남아 있는 부채
- 외부 접속 설정(주소·암호화) 미완
- 도구 등록 미완 — 확인할 때마다 같은 착오가 재발할 조건
- 계정 연결 미착수

### (덧붙임) 그 뒤 다시 올렸다

위에 적은 두 서비스는 발견 직후 다시 올렸다. 두 포트 모두 정상 응답한다.
내려간 계기는 디스크가 꽉 찼던 그 일 또는 그 뒤 재시작으로 보이지만 확정하지 못했다.

남는 문제는 원인이 아니라 **발견 방식**이다.
이건 정기 점검이 잡아준 게 아니라, 지난 기록을 되짚다가 **우연히** 걸렸다.
그 사이 며칠을 내려가 있었는지도 모른다.

지금 정기 점검은 예약 작업만 본다. **포트가 응답하는지는 아무도 안 본다.**
그래서 항목 하나를 더 넣기로 했다 — 주소를 열어 응답 코드를 확인하는 한 줄이면 된다.
