# 셀프호스팅 AI 스택 5종 검증 · 디스크 정리

SNS 홍보 채널에서 도는 "이 5개만 깔면 월 $100 구독 끊는다" 류의 인포그래픽을 받았다.
믿을지 말지를 **말이 아니라 숫자로** 정하기로 했다. 그 과정과, 하다가 터진 디스크 문제 기록.

## 🎯 목표

인포그래픽에 실린 5종(Ollama / Headroom / 9Router / Dify / OpenHands)의 진위와 도입 가치를
실측으로 판정하고, 쓸 만한 것만 가져온다.

## 🔍 1. 5종 판정

먼저 결론.

| 도구 | 판정 | 이유 |
|---|---|---|
| Ollama | 이미 있음 | 모델 4개(qwen2.5:7b, gemma3:4b 등) 설치돼 있었다 |
| Headroom | ⭕ 유일한 수확 | 토큰 압축. Apache 2.0 진본 확인 |
| 9Router | 🔴 설치 안 함 | 저장소 설명에 "구독 계정을 40개 업체로 연결" — 계정 정지 위험 |
| Dify | 🔺 보류 | Docker 필요 + 기존 워크플로 도구와 역할 중복 |
| OpenHands | 🔺 보류 | Docker 필요 + 쓰고 있는 코딩 에이전트와 같은 자리 |

**5개 전부 실존하는 오픈소스는 맞다. 낚시 그림은 아니다.**
다만 그림의 **"입력 토큰 80% 절감"은 JSON·로그 기준**이고,
만든 쪽 공식 문서에도 코딩 에이전트는 15~20%라고 적혀 있다. 숫자만 유리한 쪽을 떼온 것.

> ⚠️ 패키지명 함정: 진본은 `headroom-ai`. 그냥 `headroom` 은 **전혀 다른 사람의 다른 패키지**다.
> 이름이 비슷한 가짜를 집는 사고가 최근에도 있었어서 특히 조심해야 한다.

## 📊 2. "80% 절감"을 직접 재봤다

### 1차 측정 — 94.9%

`package-lock.json` 1.3MB를 먹여봤다.

```
1,299,226자 → 65,997자   (94.9% 절감)
```

숫자가 너무 잘 나왔다. **그래서 의심했다.**
`package-lock.json` 은 이 도구가 제일 잘하는 형태의 파일이다. 유리한 샘플 하나로 낸 값이다.

### 2차 측정 — 5.0%

만든 예제 말고 **실제 작업 세션 로그(각 22~31MB)** 로 다시 쟀다.

```
세션 A    4.5% 절감
세션 B    3.9% 절감
세션 C    6.2% 절감
────────────────────
합계      5.0% 절감
```

**19분의 1이었다.** 광고 80%, 유리한 샘플 94.9%, 실제 워크로드 5.0%.

### 그런데 딱 한 군데서는 압도적이다

에러 로그에 **같은 줄이 1595번 반복**돼 있던 파일:

```
148KB → 0.3KB   (99.8% 절감, 내용 손실 0)
```

반대로 **평범한 코드·JSON은 0%** 였다. 일부러 안 건드린다.
파일 읽은 내용을 조금이라도 바꾸면 AI가 엉뚱한 곳을 고치게 되니까. **이건 잘 만든 설계다.**

> 쉽게 말하면 — 짐을 줄여주는 도구인데, 우리 짐은 대부분 "줄이면 안 되는 짐"이었다.
> 대신 **반복 많은 로그**에는 압도적이다. 용도가 분명한 도구다.

### 측정하다 한 번 헛짚었다

처음엔 2.7%가 나왔다. 알고 보니 **압축용 로컬 모델이 아직 기동 전**이었다.
13초 기다렸다 다시 재니 5%. **콜드 스타트 상태의 벤치마크는 절반이 나온다.**

## 🧹 3. 하다가 터진 것 — 디스크가 없었다

설치하다 "공간 없음"으로 한 번 실패하고서야 알았다. **내장 디스크 잔여 695MB.**
228GB짜리가 95% 찬 상태. 여기서 작업이 통째로 방향을 틀었다.

### 3-1. 원격에 다 올라간 저장소 로컬 삭제

"깃허브에 올린 프로젝트는 지워" 지시를 받고 **먼저 되물었다.**
"로컬 복사본만? 원격 저장소는 유지?"

그리고 세어보니:

```
프로젝트 폴더 64개
├─ 완전 동기화 12개  ← 지워도 안전
└─ 로컬 전용 수정본 있음 52개  ← 지우면 작업 소실
```

12개 중에서도 삭제 직전에 3개를 더 걸러냈다.
**제일 큰 프로젝트(10GB)에 원격으로 안 올라간 커밋이 4개 있었다.** 그냥 지웠으면 사라졌다.

→ 최종 9개, 4.5GB 회수. clone 명령 + HEAD 해시가 적힌 **복구 매니페스트**를 남겼다.

### 3-2. 캐시 — 여기가 진짜 컸다

| 대상 | 크기 |
|---|---|
| 에이전트 10개가 쌓은 npm 캐시 | 153 GB (추정) |
| 각종 빌드·툴 캐시 | 46 GB |
| Node 컴파일 캐시 | 18 GB |

```bash
rm -rf <workdir>/*/.npm/_cacache
rm -rf <workdir>/*/.cache
rm -rf <tmp>/node-compile-cache
```

**추정 200GB → 실제 회수 100GB.** 절반이었다.

원인은 **`du` 합산이 하드링크를 이중 계수**한 것.
npm 캐시(`_cacache`)는 하드링크를 적극적으로 쓰는 구조라 디렉터리별로 재서 더하면 크게 부푼다.

```bash
# 추정 말고 실제 회수량을 재는 법
BEFORE=$(df -k /경로 | awk 'NR==2{print $4}')
# ... 삭제 ...
AFTER=$(df -k /경로 | awk 'NR==2{print $4}')
echo "실제 회수: $(( (AFTER-BEFORE)/1024/1024 )) GB"
```

> 되돌릴 수 없는 작업의 **승인을 받을 때 쓰는 숫자는 추정치면 안 된다.**
> 이번엔 부풀려진 값으로 승인을 받았다. 삭제 후에야 정정했다.

### 3-3. 중복 영상 105GB

100MB 초과 파일 633개를 훑었다.

- 오래된 외장하드 백업 229GB가 **통째로 중복인 것은 아니었다.**
- 대신 **그 안에서** 같은 Zoom 녹화가 여러 벌 — 63.9GB.
- 파일명+크기만 보지 않고 상위 그룹은 **앞뒤 50MB 해시까지 대조**해 동일 확인.
- 삭제는 **한 파일씩, 원본 대조 후**. 어떤 걸 지우고 뭘 남겼는지 TSV로 전부 기록.

→ 영상 69개 삭제, 71GB 회수.

## 🔧 4. 이번 최대 수확 — Ollama 저장소가 갈라져 있었다

정리하다 발견한 잠재 사고.

```
설정(.zshrc, ~/.ollama/models 심링크)  →  외장 B (26GB)
실행 중인 서버가 실제로 보던 곳        →  외장 A (11GB)
```

**터미널에서 ollama를 재시작하는 순간 설정값이 먹히면서, 모델 3개가 "사라진" 것처럼 보였을 상황이다.**

근본 원인은 **경로를 바꿔놓고 실행 중인 프로세스는 갱신하지 않은 것.**
설정을 바꾼 시점과 프로세스가 뜬 시점이 어긋나면 언제든 재현된다.

해결:
1. 한쪽에만 있던 blob 12개(3.93GB)를 통합 대상으로 복사
2. 파일명이 sha256이므로 **복사본 해시를 재계산해 검증**
3. 재시작 후 `ollama list` 6개 확인 + 실제 추론 1회 성공
4. **그 다음에** 구 경로 삭제

같은 방식으로 HuggingFace 캐시 중복 11.2GB도 정리했다.
한쪽은 백그라운드 서비스의 `HF_HOME` 이어서, **plist 경로를 먼저 바꾸고** 지웠다.
그 서비스를 다시 켜도 모델 재다운로드 없이 그대로 돈다.

## ✅ 결과

```
내장    695MB  →  17GB 여유
외장 A   65GB  → 255GB 여유
```

약 **190GB 회수.** 그리고 Headroom 하나만 가져왔다.

## 💡 배운 것

1. **광고 숫자는 유리한 샘플로 만든다.** 같은 도구가 80% / 94.9% / 5.0% / 99.8%를 오간다.
   **내 워크로드로 재기 전엔 어떤 숫자도 내 숫자가 아니다.**
2. **벤치마크 전에 워밍업.** 콜드 스타트로 재면 성능이 절반으로 나온다.
3. **`du` 합산은 하드링크를 이중 계수한다.** 캐시 용량 추정이 2배 부푼다. `df` 로 검증하라.
4. **되돌릴 수 없는 작업은 되돌릴 수 있게 만들어라.** clone 명령 + HEAD 해시 매니페스트,
   파일 단위 삭제 TSV, 설정 백업. 이게 있으면 과감해질 수 있다.
5. **"지워"라는 지시에 바로 손대지 마라.** 한 번 되물은 덕에 미푸시 커밋 4개를 살렸다.
6. **설정 변경 후 재기동까지가 한 작업이다.** 반쪽만 해두면 나중에 "파일이 사라졌다"로 돌아온다.
7. **승인을 요청할 때 쓰는 숫자는 실측이어야 한다.** 추정치를 실측처럼 말하면
   상대는 틀린 근거로 결정을 내린다.

## 🚧 남은 것

- 안 쓰는 대형 모델 18GB — 쓸 일이 있을지 판단 대기
- 교과서 자료 7.5GB 중복 — 어느 폴더를 남길지 선택 대기
- 관리자 권한이 필요한 개발 도구 잔재 약 5.7GB
- **Headroom 실효 검증** — 붙였다는 확인만 있고, 며칠 뒤 실제로 토큰이 줄었는지 재측정이 아직 없다
