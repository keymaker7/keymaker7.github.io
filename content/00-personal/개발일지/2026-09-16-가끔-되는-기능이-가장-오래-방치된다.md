# 가끔 되는 기능이 가장 오래 방치된다

하루에 두 갈래 일이 있었다. 낮에는 수업에 쓸 것을 만들었고, 밤에는 자동화 스크립트의
버그를 잡았다. 별개의 일인데 결론이 같았다 — **근거 없이 만든 것은 실측이 들어오면 무너진다.**

## 🎯 목표

전날 만든 6학년 사회 2단원 게임을 고도화한다.
저녁에 6학년 국어 2단원 면담 수행평가용 웹앱 요청이 추가로 들어와 이어서 만들었다.

## 🎮 1. 게임에 "나중에 돌아오는 선택"을 넣었다

학생이 나라 살림을 맡아 매 턴 카드 두 장 중 하나를 고르면 생산·국민행복·환경·무역신뢰
네 눈금이 움직이는 게임이다. 처음 판은 선택이 그 자리에서만 정산됐다. 그래서 **지연 결과**를 넣었다.

- 담합을 눈감으면 **3턴 뒤** 조사가 들어온다
- 야근을 밀어붙이면 **2턴 뒤** 사고가 난다

여기서 한 번 틀렸다. 벌만 지연 반영하니 **선택 자체를 무서워한다.** 아이들은 안전한 카드만 고른다.
그래서 좋은 선택도 돌아오게 했다 — 근로자를 지킨 일, 공기를 지킨 일은 나중에 주문과 평판으로 온다
(한 판 최대 3회).

카드는 30장에서 42장으로, 엔딩은 네 종 늘렸다. 엔딩이 지표 총합이 아니라
**"무엇을 눈감았는지"로 갈리게** 바꿨다.

## 📖 2. 교과서와 대조하니 없는 말이 세 개 있었다

여기가 이날의 핵심이다. 교과서 PDF를 받아 카드 문구를 하나씩 대조했더니,
**교과서에 아예 나오지 않는 낱말을 쓰고 있었다.**

| 쓰고 있던 말 | 교과서에 있는 말 |
|---|---|
| 노동조합 | 근로자의 단체 행동 |
| 담합 | 함께 가격을 올리는 문제 |
| GDP | 1인당 국민 총소득 |

세 개 다 틀린 말은 아니다. 그런데 6학년 교과서에 없다. 게임에서 GDP를 배운 아이가
교과서에서 그 말을 못 찾으면 수업이 어긋난다.

교과서 범위 밖인 FTA와 공정 무역은 지우지 않고 **「심화」 표시**만 붙였다.
교사가 판단할 수 있게 남기는 쪽이 낫다.

그리고 용어 정의 29개를 교과서 본문 문장으로 갈아 끼우고, 카드마다 교과서 쪽수를 붙였다.
되돌아보기 화면에 「교과서 69~71쪽」처럼 뜬다. 교과서에만 있던 소재로 카드 11장을 더 넣었다 —
공유지의 비극(공동 어장), 벽란도, 싱가포르, 흑연에서 배터리로, 1970년대 철강 관세.

**여기서 배운 것**: 교과 자료를 만들 때 순서가 있다. 교과서 → 성취기준 → 제작이다.
반대로 갔다가 판을 세 번 만들었다. "자료 어디 있나요" 한 줄이 재작업 두 번보다 싸다.

## 🔊 3. 소리는 파일 없이 브라우저가 낸다

재미를 붙이려고 효과음을 넣었는데, 음원 파일을 쓰지 않고 **Web Audio API로 합성했다.**
선택할 때, 눈금이 오르내릴 때, 위기가 터질 때, 정답·오답에 각각 다른 소리가 난다.

교실 인터넷이 느려도 끊기지 않는다는 게 이 방식의 이점이다. 다운로드할 게 없으니까.
대신 교실 스피커를 생각해서 **음소거 버튼을 화면에 노출**했다.

점수 계산에 한 가지 장치를 넣었다. **가장 낮은 눈금을 두 배로 가중한다.** 한 지표만 밀어붙이면
점수가 안 오른다. 균형을 맞춘 판만 등급이 올라간다.

애니메이션은 `prefers-reduced-motion`을 존중하게 처리했다.

## 🎤 4. 질문만 만들고 끝나면 수행평가가 아니다

저녁에 국어 2단원 「궁금한 점을 해결해요」 면담 수행평가 앱을 만들었다.
평가 문항은 「면담 목적에 맞는 질문을 만들고, 만든 질문을 점검하기」다.

1차로 다섯 칸을 만들었다. 이름 → 목적·대상자·방식 → 세 기준으로 질문 만들기 →
스스로 점검하고 고치기 → 제출. 교과서에 나온 세 기준(구체적 사실 / 생각·느낌 / 계획·당부)을
칸으로 나눠 채우게 했다.

지적을 받았다. **"실제 면담에 활용할 수 있게 제작해줘야지."** 맞는 말이었다.
질문지를 만드는 도구였고, 면담을 하는 도구가 아니었다.

그래서 세 화면을 붙였다.

- **면담 요청** — 날짜·장소를 적으면 학생이 쓴 목적·대상자로 요청하는 말이 완성된다.
  녹음 허락을 구하는 말이 반드시 들어간다. 전화·방문·메일 어디에나 복사해 쓴다.
- **면담하기** — 면담 중에 펴 놓는 화면. 열기 대본 세 줄, 녹음 동의 체크, 경과 시간,
  질문을 한 장씩 넘기며 답변 받아 적기, 그 자리에서 후속 질문 덧붙이기.
  손으로 치기 어려운 학생을 위해 **Web Speech API 음성 입력**을 붙였다.
  안 되는 기기에서는 그렇다고 알려 주고 글자판으로 쓰게 한다.
- **정리·보고서** — 질문·답변 표, 되돌아보기 세 항목, 그리고 **적어 둔 것만 이어 붙인 보고서 초안.**
  지어내지 않는다. 학생이 자기 말로 고친 뒤 인쇄하면 보고서 한 장이 된다.

구술 평가이므로 화면의 판정은 **초안**이고, 최종은 교사가 정한다고 화면에 못 박았다.
서버도 로그인도 없다. 학생이 제출 코드를 복사해 클래스룸에 붙이면 교사 화면에 명단으로 들어간다.

자정 무렵에 마지막 요청을 받았다. "면담의 절차도 학생들이 면담을 하면서 익힐 수 있는 구조면 좋겠다."
그래서 화면을 아홉 칸으로 늘리고 상단 띠를 **준비하기 · 진행하기 · 정리하기** 세 덩어리로 묶었다.
지금 칸이 교과서 절차 몇 단계인지 항상 한 줄로 뜬다. 활동을 하면서 절차 이름을 저절로 듣게 되고,
마지막 칸에서 그 절차를 문제로 확인한다.

## 🐛 5. 감시 스크립트가 완료 배너를 "아직 하는 중"으로 읽었다

이날 밤 잡은 버그가 이 글의 제목이 된 이유다.

여러 봇을 tmux 세션으로 띄워 두고, 쉘 스크립트가 10초마다 화면을 떠서 상태를 본다.
입력창에 글자가 남아 있는데 Enter가 안 먹은 상태면 대신 제출해 주는 구제 로직이 있다.

며칠째 **지시가 제출되지 않고 방치되는 일**이 반복됐다. 하루에 몇 건은 되고 몇 건은 안 됐다.

원인은 진행 여부를 판정하는 방식이었다. 진행 중인지를 화면 단어 목록으로 봤다.

```bash
# 문제가 된 코드
if echo "$pane_out" | grep -qE "Thinking|Baked|Cooked|Cogitat|Churning|Running"; then
    continue   # 이미 처리 중이니 건드리지 않는다
fi
```

그런데 이 CLI는 작업이 **끝나면** 이런 배너를 남긴다.

```
✻ Baked for 13m 47s · done 7:18 PM
✻ Cogitated for 22m 10s · done 7:22 PM
```

`Baked`가 목록에 있다. **완료 문구가 "처리 중"으로 읽혔다.**
완료 배너는 다음 작업이 시작될 때까지 화면에 남는다. 그래서 교착이 된다 —
봇은 지시가 미제출이라 멈춰 있고, 스크립트는 바쁜 줄 알고 제출을 안 한다.
실측했을 때 미제출 상태였던 넷이 전부 이 분기에서 건너뛰어졌고, 넷 다 상태줄은 유휴였다.

### 왜 며칠이나 안 잡혔나

**가끔 됐기 때문이다.** 마지막 단어가 우연히 목록에 없으면(`Churned`, `Frolicking`)
제출이 됐다. 이틀에 두 건이라도 되니까 "느리지만 돌아간다"로 보였다.

완전히 죽은 기능은 바로 고친다. 가끔 되는 기능은 오래 방치된다.
간헐적 성공이 문제를 덮는다.

### 고친 방식

근본 원인은 목록이 불완전했던 게 아니다. **작업 내용에 따라 달라지는 문자열로 상태를 판정한 것**이다.
목록을 늘려도 다음 단어에서 또 터진다.

그래서 단어 목록을 지우고, 이 CLI가 **고정으로 그리는 UI 문자열** 하나만 보게 했다.

```
진행 중 → ⏵⏵ bypass permissions on … · esc to interrupt · …
유휴   → ⏵⏵ bypass permissions on (shift+tab to cycle) · ← for agents
```

`esc to interrupt`는 UI 자체라 작업 내용에 좌우되지 않는다.

부작용이 하나 생긴다. 제출이 훨씬 자주 일어나니 **사람이 치고 있는 도중을 낚아채** 반쪽 문장을
보낼 위험이 커진다. 그래서 안정화 대기를 붙였다.

```bash
# 같은 문장이 45초간 글자 하나 안 바뀐 채 남아 있을 때만 제출한다
STABLE_SECS=45
# 타이핑 중이면 그 사이 내용이 바뀌어 타이머가 초기화된다
```

## 📊 이날의 검증

교실에서 쓸 물건이라 실측은 남겨 둔다.

- 게임: 시드 고정 자동 플레이 3판 + 라이브 1판, 엔딩까지 오류 없음 →
  교과서 대조 후 4판 재검증
- 카드 수는 소스에서 뽑는다: `grep -c "situation:" src/cards.ts`
- 배포 반영 확인: 라이브 번들 해시가 로컬 빌드 산출물과 일치하는지 대조
- 참고한 오픈소스는 CC BY-NC라서 출처를 제목 화면에 표기했고, 실제로 코드에 들어갔는지 grep으로 확인

교사용 안내 A4 한 장과 학생용 활동지 A4 한 장을 PDF로 뽑았다.
html 원본을 같은 폴더에 두어 고칠 곳이 생기면 다시 출력된다.

## 🧾 남은 일

- 게임과 면담 앱 둘 다 **아직 git 저장소가 아니다.** 이틀에 일곱 번 재배포했는데 되돌릴 지점이 없다.
  스크린샷 폴더만 세대별로 쌓였다. 스크린샷은 무엇이 보였는지는 남기지만 무엇을 바꿨는지는 남기지 않는다.
- 두 앱의 **접근 권한 설정을 다시 맞춰야 한다.** 다루는 정보의 민감도와 보호 수준이
  서로 어긋나 있었다. 검토 대상.

## 🔑 정리

1. **교과 자료는 교과서부터.** 추측으로 만들면 교과서에 없는 말이 섞인다. 세 개 나왔다.
2. **벌만 지연 반영하면 선택을 회피한다.** 좋은 선택도 나중에 돌아오게 해야 게임이 된다.
3. **가끔 되는 기능이 가장 오래 방치된다.** 죽은 기능은 바로 고치지만, 간헐적 성공은 문제를 덮는다.
4. **UI 상태는 UI가 고정으로 그리는 문자열로만 판정한다.** 작업 내용에 따라 달라지는 문자열을
   판정에 쓰면 언젠가 반드시 겹친다.

## 📋 선임 리뷰 — 이날의 나에게

### 잘한 것
**교과 근거를 두 번 되짚었다.** 게임을 더 재미있게 만들기 전에 교과서와 대조해서
"이 활동이 어느 성취기준에 붙는가"를 확인했다. 수업 자료는 재미보다 근거가 먼저다.

**남의 연출을 참고할 때 원본을 직접 열어봤다.** 설명만 읽고 흉내 내지 않았다.

### 반복된 나쁜 패턴
1. **"고도화해봐"를 확인 없이 다른 작업으로 집행했다.** 나는 그 말을 접근 제한 추가로 알아듣고 먼저 만들었다. 사흘 전에도 같은 구조의 오독이 있었다. **한 줄 질문이면 되는 것을 만들고 나서 확인했다.**
2. **비밀값이 다시 대화창에 올라갔다.** 2주 전 같은 사고가 있었는데 같은 패턴이 반복됐다. 값은 바꿀 수 있지만 **기록은 남는다.**
3. **보고 수치를 소스에서 뽑지 않았다.** 카드 개수를 57이라고 보고했는데 뒤에 58로 보였고, 나흘 뒤 다시 세어보니 **57이 맞았다**(58은 카드가 아닌 선언 한 줄을 같이 센 것). 어느 쪽이든, 눈으로 세지 말고 명령으로 뽑았어야 나흘을 안 썼다.
4. **배포물에 버전 관리가 없다.** 아이들에게 나갈 자료를 계속 덮어쓰고 있다. 사흘 뒤 확인했을 때도 그대로였다.
5. **두 앱의 보호 수준이 다른데 근거가 없었다.** 한쪽은 잠겨 있고 다른 쪽은 열려 있었다 — 다루는 정보의 민감도로 정해진 게 아니라 만든 순서대로였다.
6. **자동 제출 장치가 세 번째 사후 수정을 받았다.** 매번 증상만 고쳤고, 근본 원인은 이번에야 규명했다.

### 다음에 똑같이 안 당하려면
- **비밀값은 요청이 와도 대화창에 쓰지 않는다.** 경로나 클립보드로만 넘긴다. 판단이 개입하면 언젠가 틀린다.
- **배포 전 첫 단계로 버전 관리를 넣는다.** 자료가 늘어난 뒤에 넣으면 이전 버전은 이미 없다.
- **보고 수치는 명령으로 뽑는다.** 세어서 말한 숫자는 나중에 다시 세게 된다.
- **한 단어로 온 지시는 착수 전에 한 줄로 확인한다.** "고도화"가 무엇인지는 두 가지로 읽힌다.
- **보호 수준은 다루는 정보로 정한다.** 만든 순서로 정하지 않는다.

### 남아 있는 부채
