# 셀프호스팅 AI 스택 5종 검증

SNS 홍보 채널에서 도는 "이 5개만 깔면 월 $100 구독 끊는다" 류의 인포그래픽을 받았다.
믿을지 말지를 **말이 아니라 숫자로** 정하기로 했다. 그 과정 기록.

## 🎯 목표

인포그래픽에 실린 5종(Ollama / Headroom / 9Router / Dify / OpenHands)의 진위와 도입 가치를
실측으로 판정하고, 쓸 만한 것만 가져온다.

## 🔍 1. 5종 판정

먼저 결론.

| 도구 | 판정 | 이유 |
|---|---|---|
| Ollama | 이미 있음 | 모델 4개(qwen2.5:7b, gemma3:4b 등) 설치돼 있었다 |
| Headroom | ⭕ 유일한 수확 | 토큰 압축. Apache 2.0 진본 확인 |
| 9Router | 🔴 설치 안 함 | 저장소 설명에 "구독 계정을 40개 업체로 연결" — 계정 정지 위험 |
| Dify | 🔺 보류 | Docker 필요 + 기존 워크플로 도구와 역할 중복 |
| OpenHands | 🔺 보류 | Docker 필요 + 쓰고 있는 코딩 에이전트와 같은 자리 |

**5개 전부 실존하는 오픈소스는 맞다. 낚시 그림은 아니다.**
다만 그림의 **"입력 토큰 80% 절감"은 JSON·로그 기준**이고,
만든 쪽 공식 문서에도 코딩 에이전트는 15~20%라고 적혀 있다. 숫자만 유리한 쪽을 떼온 것.

> ⚠️ 패키지명 함정: 진본은 `headroom-ai`. 그냥 `headroom` 은 **전혀 다른 사람의 다른 패키지**다.
> 이름이 비슷한 가짜를 집는 사고가 최근에도 있었어서 특히 조심해야 한다.

## 📊 2. "80% 절감"을 직접 재봤다

### 1차 측정 — 94.9%

`package-lock.json` 1.3MB를 먹여봤다.

```
1,299,226자 → 65,997자   (94.9% 절감)
```

숫자가 너무 잘 나왔다. **그래서 의심했다.**
`package-lock.json` 은 이 도구가 제일 잘하는 형태의 파일이다. 유리한 샘플 하나로 낸 값이다.

### 2차 측정 — 5.0%

만든 예제 말고 **실제 작업 세션 로그(각 22~31MB)** 로 다시 쟀다.

```
세션 A    4.5% 절감
세션 B    3.9% 절감
세션 C    6.2% 절감
────────────────────
합계      5.0% 절감
```

**19분의 1이었다.** 광고 80%, 유리한 샘플 94.9%, 실제 워크로드 5.0%.

### 그런데 딱 한 군데서는 압도적이다

에러 로그에 **같은 줄이 1595번 반복**돼 있던 파일:

```
148KB → 0.3KB   (99.8% 절감, 내용 손실 0)
```

반대로 **평범한 코드·JSON은 0%** 였다. 일부러 안 건드린다.
파일 읽은 내용을 조금이라도 바꾸면 AI가 엉뚱한 곳을 고치게 되니까. **이건 잘 만든 설계다.**

> 쉽게 말하면 — 짐을 줄여주는 도구인데, 우리 짐은 대부분 "줄이면 안 되는 짐"이었다.
> 대신 **반복 많은 로그**에는 압도적이다. 용도가 분명한 도구다.

### 측정하다 한 번 헛짚었다

처음엔 2.7%가 나왔다. 알고 보니 **압축용 로컬 모델이 아직 기동 전**이었다.
13초 기다렸다 다시 재니 5%. **콜드 스타트 상태의 벤치마크는 절반이 나온다.**

## 🔧 4. 이번 최대 수확 — Ollama 저장소가 갈라져 있었다

점검하다 발견한 잠재 사고.

```
설정 파일이 가리키는 모델 폴더   →  A
실행 중인 서버가 실제로 보던 곳  →  B
```

**서버를 재시작하는 순간 설정값이 먹히면서, 모델 몇 개가 "사라진" 것처럼 보였을 상황이다.**

근본 원인은 **경로를 바꿔놓고 실행 중인 프로세스는 갱신하지 않은 것.**
설정을 바꾼 시점과 프로세스가 뜬 시점이 어긋나면 언제든 재현된다.

해결 순서:
1. 한쪽에만 있던 파일을 통합 대상으로 복사
2. 파일명이 sha256이므로 **복사본 해시를 재계산해 검증**
3. 재시작 후 `ollama list` 와 실제 추론 1회로 확인
4. **그 다음에** 옛 경로를 정리

순서가 핵심이다. 확인보다 정리를 먼저 하면 되돌릴 수 없다.

## ✅ 결과

5종 중 **Headroom 하나만** 가져왔다. 나머지는 내 워크로드에서 값을 못 했다.

## 💡 배운 것

1. **광고 숫자는 유리한 샘플로 만든다.** 같은 도구가 80% / 94.9% / 5.0% / 99.8%를 오간다.
   **내 워크로드로 재기 전엔 어떤 숫자도 내 숫자가 아니다.**
2. **벤치마크 전에 워밍업.** 콜드 스타트로 재면 성능이 절반으로 나온다.
3. **승인을 요청할 때 쓰는 숫자는 실측이어야 한다.** 추정치를 실측처럼 말하면
   상대는 틀린 근거로 결정을 내린다.

## 🚧 남은 것

- **Headroom 실효 검증** — 붙였다는 확인만 있고, 며칠 뒤 실제로 토큰이 줄었는지 재측정이 아직 없다
