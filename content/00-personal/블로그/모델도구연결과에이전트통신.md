# MCP와 ACP 차이

## 🎯 한 줄 요약

MCP는 모델이 파일, 검색, 데이터베이스 같은 바깥 도구를 쓰게 만드는 연결 규약이다. ACP는 에이전트끼리 일감을 주고받고 상태를 공유하게 만드는 통신 규약이다.

내가 이 둘을 구분할 때 제일 빨랐던 기준은 기술 이름이 아니라 **상대가 누구냐**였다. 상대가 도구면 MCP고, 상대가 다른 에이전트면 ACP다.

## 1. MCP는 어디에 쓰나

[Model Context Protocol 공식 소개](https://modelcontextprotocol.io/docs/getting-started/intro)는 MCP를 “AI 애플리케이션이 LLM에 컨텍스트를 제공하는 표준화된 방식”으로 설명한다. [공식 GitHub 저장소](https://github.com/modelcontextprotocol/modelcontextprotocol)는 이 저장소가 사양, 스키마, 공식 문서를 함께 담고 있다고 적어둔다.

실무 감각으로 풀면 더 쉽다. MCP는 모델이 바깥 도구를 일정한 방식으로 발견하고, 입력을 보내고, 결과를 다시 받게 만드는 접점이다.

| 질문 | MCP에서 보는 관점 |
|---|---|
| 모델이 뭘 붙잡나 | 파일, 브라우저, DB, API, 검색 |
| 왜 필요하나 | 도구마다 제각각인 호출 방식을 줄이려고 |
| 언제 체감되나 | 도구 수가 3개를 넘어가고 연결이 반복될 때 |

예를 들면 이런 요청이 MCP에 가깝다.

- 이 폴더 파일 목록 보여줘
- 깃허브 이슈 읽어와
- 데이터베이스에서 고객 상태 조회해
- 브라우저로 로그인 화면 열어

핵심은 **모델과 도구 사이 표준화**다.

---

## 2. ACP는 어디에 쓰나

[Agent Communication Protocol 문서](https://agentcommunicationprotocol.dev/introduction/welcome)는 ACP를 “에이전트 상호운용성을 위한 오픈 프로토콜”이라고 설명한다. 같은 문서 첫 화면에는 **ACP가 Linux Foundation 아래 A2A 쪽으로 합류했다**는 안내도 붙어 있다. [IBM Research 소개](https://research.ibm.com/projects/agent-communication-protocol)도 ACP를 “프레임워크, 언어, 런타임과 무관하게 AI 에이전트끼리 통신하게 만드는 경량 HTTP 기반 표준”으로 설명한다.

여기서 중요한 포인트는 도구가 아니라 **다른 에이전트**다.

| 질문 | ACP에서 보는 관점 |
|---|---|
| 에이전트가 누구와 말하나 | 다른 에이전트, 애플리케이션, 사람 |
| 왜 필요하나 | 위임, 상태 공유, 장기 작업 추적을 맞추려고 |
| 언제 체감되나 | 리서치, 작성, 검수처럼 역할이 분리될 때 |

예를 들면 이런 흐름이 ACP에 가깝다.

- 리서치 에이전트가 자료를 수집한다
- 작성 에이전트가 초안을 만든다
- 검수 에이전트가 사실관계를 체크한다
- 오케스트레이터가 각 상태를 모아서 최종 결과를 낸다

핵심은 **에이전트 협업 표준화**다.

---

## 3. 한 번에 구분하는 표

| 항목 | MCP | ACP |
|---|---|---|
| 연결 대상 | 모델 ↔ 도구 | 에이전트 ↔ 에이전트 |
| 해결하려는 문제 | 도구 호출 방식 통일 | 협업 메시지 방식 통일 |
| 대표 장면 | 파일 읽기, 검색, DB 조회 | 위임, 상태 보고, 결과 반환 |
| 자주 나오는 인터페이스 | 도구 설명, 입력 스키마, 결과 payload | 메시지, 작업 상태, 동기·비동기 흐름 |
| 내가 기억하는 한 줄 | 도구를 붙인다 | 팀을 묶는다 |

---

## 4. 내가 실제로 구분하는 기준

체감상 이 기준이 제일 빨랐다.

- 상대가 파일 시스템, 브라우저, 검색 엔진이면 MCP 쪽이다.
- 상대가 리서치 에이전트, 작성 에이전트, 검수 에이전트면 ACP 쪽이다.
- 둘이 같이 들어가는 구조도 많다. 에이전트는 ACP로 협업하고, 각 에이전트는 내부에서 MCP로 도구를 쓸 수 있다.

이 마지막 줄이 꽤 중요하다. 아키텍처를 보면 MCP와 ACP는 경쟁 관계가 아니라 **서로 다른 층**에 있는 경우가 많다.

---

## ⚠️ 자주 나오는 오해

| 오해 | 현실 |
|---|---|
| MCP면 여러 에이전트 협업까지 다 해결된다 | MCP는 주로 모델과 도구 연결 문제를 푼다 |
| ACP는 MCP의 상위 버전이다 | 상하 관계보다 대상과 층이 다르다 |
| ACP는 이미 업계에서 하나의 이름으로 완전히 굳었다 | 공개 표준 문서가 있지만, 문맥에 따라 A2A와 함께 보거나 다른 명칭을 쓰기도 한다 |

---

## 5. 설계 예시 하나

\`사용자 요청 → 오케스트레이터 에이전트 → 리서치 에이전트 / 작성 에이전트 / 검수 에이전트 → 최종 응답\`

이 구조라면 에이전트끼리 메시지를 주고받는 흐름은 ACP 쪽 사고가 잘 맞는다. 반대로 리서치 에이전트가 검색 도구를 쓰고, 작성 에이전트가 파일 시스템을 읽고, 검수 에이전트가 저장소를 조회하는 장면은 MCP 쪽 사고가 잘 맞는다.

즉 한 시스템 안에서도 둘은 같이 나온다.
